# 复盘入库（retro）

这是项目"越用越聪明"的唯一途径。不做复盘，下一单还会犯同样的错。

## A. 口吻学习（随时触发）
触发：主理人改了你的草稿再发 / 主理人说"我会这样说……" / 主理人提供了新的聊天样本。

1. 对比"草稿"和"实际发出"，找出差别：称呼、语气词、句长、删掉了什么、加了什么。
2. 把实际发出的那条加进 `db/口吻/范例.md` 对应场景（去掉客户真实姓名、学校、电话）。
3. 如果差别反映出稳定的习惯（比如"从不用'您好'开头"），更新 `db/口吻/画像.md`，并在"变更记录"写一行。
4. 一次只改有把握的规律；只出现一次的，先记在画像的"待观察"里。

## B. 订单复盘（一单结束时）
1. 按 `模板/案例.md` 写 `db/案例/<日期>_<订单名>.md`（不写客户真实姓名、电话、学校全称）。
   重点写："哪些问题第一轮就该问但没问""客户真正在意的"。
2. 判断有没有**通用经验**：
   - 新的必问项 → 加进对应 `清单/*.md`；
   - 新的设计规范、技术做法、坑 → 加进 `db/经验/playbook.md` 对应章节；踩坑表里已有的坑，次数 +1。
3. 有复用价值的脚本，复制到 `db/经验/scripts/<用途>/` 并写两行用法。
4. 给主理人一段汇报：本单入库了哪些东西（文件 + 一句话）。

## 原则
- 只写验证过的经验；推测标"推测"。
- 改清单和 playbook 要克制：写成一条可执行的规则，而不是一段故事。
- 隐私：案例和范例里只留称呼（"王老师""某高校课程"）。
