# 制作（build）

**动手前确认**：理解卡"开工门槛：已通过"，且主理人确认过方案摘要。没有就退回 intake/ask。

## 必读
- `db/经验/playbook.md` 全文（第 0 节 12 条速查、第 5 节设计规范、第 6 节技术做法、第 7 节踩坑表）。
- `db/案例/` 里同类案例的"可复用资源"。

## 选做法（摘自 playbook 第 3 节）

| 任务 | 做法 |
|---|---|
| 美化/修改客户现有 .pptx | **Windows + PowerPoint COM 原地改**（保动画、触发器、音视频），按 shape id 定位 |
| 从讲稿/课本新做、要可编辑 | pptxgenjs 或 python-pptx 脚本生成，脚本保留可重跑 |
| 视觉拉满的演讲 | 先 HTML 出效果，再做原生 PPTX；不要"每页一张截图"的 pptx |
| PowerPoint 做不到的连续动效 | 浏览器逐帧渲染 → ffmpeg 出 MP4 → 嵌入 PPT 自动播放 |
| 手绘/彩铅特殊质感 | 程序生成透明 PNG + 原生文本框（告知：框线不能一键改色） |
| 多份同模板批量统一 | 自动引擎 + PowerPoint 实测 + 逐页高清复查，留人工精修时间 |
| 提案/画册 PDF | HTML → PDF，嵌入字体 |

**环境不符时**（例如在 Mac 上要改带动画的客户 PPT）：先告诉主理人风险和替代方案，不要硬做。

## 工作区约定
```
订单/<名>/
├─ 材料/        客户原件（只读）
├─ 工作/        脚本、中间文件、导出的 PNG
└─ 成品/        v1、v2…；对比/ 放前后对比图
```
- 每次从原件重建，脚本可重复执行。
- 输出文件被占用（主理人/客户开着）→ 另存下一个版本号，不要关闭别人的文件。

## 先出样张
风格不确定或改动大时，先做 1～2 页代表性页面（封面 + 一页典型内容页），导出 PNG 给主理人转发确认，再铺全篇。

## COM 必守（Windows）
```python
import win32com.client as wc
app = wc.DispatchEx('PowerPoint.Application')
assert 'Office16' in app.Path, 'not real PowerPoint: ' + app.Path   # 防 WPS 劫持
# ……只关闭本脚本打开的那个演示文稿，绝不"关闭全部"
```
- 文字尺寸用 PowerPoint 实测（AutoSize 量一次再关），不估算。
- 动画在 XML 层与原稿逐条比对。

## 质检（交付前全部做完，做不到的写进交付说明）
1. **渲染**：导出每页 PNG，高分辨率逐页看（不是只看缩略图）。问题页修完单独复查。
2. **文字**：与原稿逐页做非空白字符计数比对，只允许有意的增删。
3. **版面**：最小字号、溢出、重叠、越界、卡片挡字/挡图、标点出现在行首。
4. **动画**（改现有稿时）：XML 级比对数量与类型。
5. **统一性**：正文字号、行距、边距、标题样式全篇一致。
6. **客户条目**：理解卡和问答记录里的每一条要求，逐条打勾。
7. **兼容**：特殊字体是否换成微软雅黑或已嵌入；WPS 不支持的效果有没有提醒。

## 交付
- 美化单：生成逐页前后对比图（原稿 | 新稿）放 `成品/对比/`。
- 按 `模板/交付说明.md` 写交付说明，其中"发给客户的"部分用主理人口吻（先读 `db/口吻/`）。
- 交付说明里明确：改了什么（逐条对应客户要求）/ 我额外加的 / 验证了什么、没验证什么 / 需要确认的点。
