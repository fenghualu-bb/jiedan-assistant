## 0. 一页速查（最重要的 12 条）

1. **先读懂、先汇报理解，再动手。** 用户几乎每单都要求“先整体理解 → 合理规划 → 再执行”。有截图圈注时，先复述你理解的范围（圈一处 = 改这一类）。
2. **改现有 PPT 用 PowerPoint COM 原地改**，不要整份重生成：形状 id 不变，动画、触发器、音视频才能保住。
3. **连接 PowerPoint 用 `DispatchEx` 并断言 `app.Path` 含 `Office16`**。WPS 开着时，`EnsureDispatch/Dispatch` 会拿到 WPS 冒充的对象，结果静默出错（这个坑踩了两次）。
4. **渲染检查用 PowerPoint 导出 PNG，并按高分辨率逐页看。** “只看缩略图”的那几章，后面返工了三轮。
5. **文字测量用 PowerPoint 实测，不要估算。** 估算文字高度是“字叠在一起、白卡片盖不住字”的根本原因。
6. **动画要在 XML 层和原稿逐条比对**，COM 读回的结果不可信（会悄悄丢动画、交互序列的触发类型读不准）。
7. **4:3 → 16:9 必须真正重排**，铺满宽度；只改尺寸居中会被客户直接否决。
8. **“统一”在客户眼里是“看起来差不多”**：正文统一一个字号（20 号）、统一行距（1.3），不要为了塞下去把行距降到 1.1。
9. **客户付了钱就要“看得出变化”**：交付时附原稿/新稿逐页对比图；改动要落在显眼处（结构页、版式、卡片化），不是只换细节。
10. **简洁优先**：校徽、学校名、零碎小图标、装饰小圆球、跳转链接，客户都主动要求删掉过。
11. **只说验证过的**：没放映就说没放映，没在 WPS 打开过就说没测；事实存疑（人物年龄、照片是否本人、装订方向）要查，查不到就明说。
12. **永远不碰用户自己的文件**：不要“关闭所有演示文稿”；文件被占用就另存新名并告诉用户。

## 2. 需求理解：反复出现的客户模式

### 2.1 客户真正在意的东西
- **“看得出改了”**：工程制图那单 v4 后客户说“变化不多，花钱没看到效果”。原因：最占视觉的图线、模型、卡通人没动，改的是导航栏、字重这些细节；早期“首页改回原样、不能动图片位置”的约束也让方案偏保守。
  - 有效的补救：加结构页（目录/章节过渡页）、图线页垫“图纸框”、散排页改卡片、**交付附逐页前后对比图**。
  - 教训：第一轮就要问清“允许重排每页的图文位置吗？”，别等客户不满意再问。
- **“统一”= 看起来差别不大**：客户说“有的字特别大，有的间距特别密，差距不能太大”。第一轮只把零碎字号取整到标准档位、保留了原有大小关系，等于没解决。第二轮改成正文一律 20 号才过关。
- **“16:9”= 内容铺满宽度**：只改页面尺寸、内容仍在中间 10″ 宽区域，被客户原话否决：“还是堆在中间，仍然是 4:3”。
- **少翻页**（演讲类）：演讲稿那单从 27 页压到 15 页，每页动画进页后自动依次播放、页内不设点击。理由是“一直翻页会让演讲显得破碎”。
- **简洁 > 装饰**：被客户删掉过的东西有校徽、学校中英文名、卡片里的小插图、零散小星星、装饰小圆球、视频链接文字。客户原话的意思是：小图片没用，会对听众造成信息干扰。
- **同一层级用同一种视觉**：彩铅那单客户要求“紫色箭头后面跟紫色小箭头”，同一行的元素用一个颜色。

### 2.2 客户表达方式
- 截图 + 红圈/红线/黑圈 + 语音转文字。红圈圈的是“这一类”，适用于全册。
- 页码常有出入（说“第 26 页”其实在第 25 页）。有歧义就先说出你的理解再做。
- 前后指令会冲突（“首页改回原样” vs 后来“可以重新设计整体风格”；“字号 ≥24” vs “中文小一点无所谓”）。以最新指令为准，但**明确点出冲突**。
- 用户转述客户反馈时，先汇报“我是这样理解的”，确认后再改（11-09、11-12 两单用户都明确要求先汇报）。

### 2.3 主动发现问题，但不擅自改内容
被用户认可的做法：
- 指出讲稿/原稿里的错字、标点（英文逗号）、逻辑问题（“三维进阶”下面列了四条目标），**列出来让用户决定**，明显笔误可以直接改并在交付说明里写清。
- 事实存疑要查：账本翻页方向（查到中式线装书右侧装订、从左向右翻，并修正）、“陈云十二岁学记账”（查不到可靠出处，明说）、照片是不是本人（不是就明说）。
- 改内容、改画法（如工程图线型是否符合国标）属于“需要客户拍板”，只建议不动手。
- 自己加的内容（翻译小字、补的流程行、示意数据）一律在交付说明里标出“这是我加的”。

## 3. 选型：什么任务用什么做法

| 任务 | 推荐做法 | 理由 / 实际经验 |
|---|---|---|
| 美化/修改客户现有 .pptx | **PowerPoint COM 原地改**（Python pywin32） | 保住动画、触发器、音视频；所有美化单都这么做 |
| 从讲稿/课本新做、要可编辑 | pptxgenjs 或 python-pptx 脚本生成 | 数学课、说课稿都这么做；脚本保留，改配色/页数可重跑 |
| 视觉拉满的演讲 | 先 HTML 出效果，再做**原生 PPTX** | 用户最终要的是 pptx；“每页一张截图”的 pptx 被用户否定 |
| PowerPoint 做不到的连续动效（3D 翻书） | 浏览器逐帧渲染 → ffmpeg 编码 MP4 → 嵌入 PPT 自动播放 | 用多页“平滑切换”拼翻书不丝滑，像一张张照片在跳 |
| 手绘/彩铅等特殊质感 | 程序生成透明 PNG（框、箭头）+ 原生文本框 | 代价：框和箭头不能一键换色，要重新生成 |
| 多份同模板课件批量统一 | 自动引擎 + PowerPoint 实测 + 逐页高清复查 | 自动排版对复杂页质量低，必须留人工精修时间 |
| 提案/画册类 PDF | HTML → PDF | 软装提案；字体嵌入，PDF 自身渲染检查 |

**本机已装的 skill**（11-06 安装）：ppt-master（原生可编辑 pptx，含动画/切换 XML 工具）、huashu-design、frontend-slides、guizang-ppt-skill、academic-pptx、frontend-design、canvas-design、theme-factory，以及内置 pptx/pdf/docx。实际最常用的是**内置 pptx skill 的读取脚本 + 自己写 COM 脚本**；ppt-master 的 `pptx_animations.py`、`pptx_transitions.py` 在演讲稿那单被借用来写动画/切换 XML。

## 4. 标准工作流程

1. **备份**：原件只读；改之前备份到 `备份_日期` 文件夹。每一轮的成品都留着（v1、v2…），用户随时可能要求“恢复上一版”。
2. **盘点**：每页形状 id/类型/位置/字体字号、动画序列；导出原稿 PNG 逐页看。
3. **汇报理解与方案**（尤其是转述客户反馈的时候），等确认。
4. **定设计系统**：色板、字号档位、标题样式、卡片样式、安全边距（见第 5 节）。
5. **构建**：脚本可重复执行，每次从原件重建，按 shape id 定位（名字会重复、会被本地化）。
6. **QA**：
   - 文字：与原稿逐页做非空白字符计数比对，只允许有意的增删。
   - 动画：XML 级逐条比对。
   - 版面：最小字号、溢出、重叠、越界、白卡片是否盖住文字/是否挡图。
   - 渲染：PowerPoint 导出 PNG，**高分辨率逐页看**，问题页修完单独复查。
7. **交付说明**：改了什么 / 我加了什么 / 哪些没验证（放映、WPS）/ 需要客户确认的点。美化单附前后对比图。

## 5. 被客户认可的设计规范（可直接复用）

### 5.1 固废课程（极简学术风，客户确认的标准）
- 16:9，13.333″×7.5″，内容左右边距约 0.6″，铺满宽度。
- 封面/节标题：全宽蓝色横带 `#1A5F9A` + 白字，左下橙色小竖条 `#EE8742`。
- 内容页标题：左上实心蓝色矩形，白色粗体 24pt 左对齐。
- 背景浅蓝 `#E8F0F9`，正文放白色卡片（卡片不能挡图）。纯白背景被客户嫌“太空、太单调”。
- 字体全部微软雅黑；字号只用 28/24/20/18/16；正文 `#333333`，小标题蓝，重点词红 `#C0392B`。
- 无动画、阴影、3D、校徽、学校名。

### 5.2 跨文件字体间距统一（第 1/3/4/5/6 章）
- 正文 20 号（放不下才用 18，再不行 16），页内小标题 22 号。18 号试过：字少的页大半空着，更难看。
- 行距 1.3 倍、段前 6 磅；**不为塞下而降行距**，放不下就调文本框大小或挪图。
- 白色内容框左边缘与标题条左对齐。
- 打开“按中文习惯控制首尾字符”（标点不出现在行首）。
- 项目符号显式写成“无”，避免 WPS 和 PowerPoint 显示不一致。

### 5.3 工程制图课件（白底 + 清新蓝）
- 有大量图线的课件：背景必须纯白，不加网格、纹理。
- 图线里的红色中心线、品红作图线、黑色轮廓线是**教学语义**，不能改色。
- 正文去掉加粗，只加粗关键词（几乎全加粗时重点反而不突出）。
- 有效的“精致化”手段：导航栏重设计、双色章节标签、步骤进度条（形体分析 › 视图选择 › 画图）、图线页垫图纸框 + 标题栏、思考环节统一成“想一想”对话卡片、散排页卡片化、统一淡入切换。

### 5.4 说课/比赛课件
- 讲稿全文放进每页备注，方便演讲者视图读。
- “数智化/AI”主题：每个环节一个固定位置的“本环节 AI/数智技术”面板。工具写通用类别，备注里给产品举例，让老师按实际核对。
- 示意性数据标“示意”，提醒替换真实数据。
- 科技感做“轻科技风”：浅色底纹（电路线最贴主题）、HUD 框角、发光节点。不建议整套深色霓虹（白底素材会变刺眼白块，也和学科气质不符）。**先出样张让客户选**，再铺全篇。

### 5.5 演讲类（《一把算盘的接力》）
- 主题元素要一眼可见（账本：朱丝栏、线装、印章、大写页码、算珠进度条）。
- 页面不照搬讲稿，只放关键词，其余做成视觉（金额格数字翻动、地图箭头、价格曲线、昔/今对照）。
- 只用真实照片（维基共享资源），每张图下方小字标来源。
- 背景音乐：跨页循环、压低音量、首尾淡入淡出。**选曲要核对作者的风格标注**——第一首《Tea Roots》被用户说“像在搞怪”，查下来是雷鬼风格，只因带二胡被误选。我听不到音乐，必须让用户试听。

## 6. 关键技术做法

（COM 细节、代码片段见附录 5 节，这里只列跨任务新增或强化的。）

### 6.1 连接真正的 PowerPoint
```python
import win32com.client as wc
app = wc.DispatchEx('PowerPoint.Application')      # 新建独立实例
assert 'Office16' in app.Path, 'not real PowerPoint: ' + app.Path
```
- 11-09 第 6 章时 WPS 开着，用这个写法拿到的是真 PowerPoint，成品确认由 PowerPoint 保存（已验证）。
- 11-11 用 `gencache.EnsureDispatch` 时被 WPS 劫持；当时直接启动 POWERPNT.EXE 也没用（运行对象表仍给 WPS）。两次的差别在于 `DispatchEx` 新建实例、`Dispatch/EnsureDispatch` 取已有对象。**推测**：`DispatchEx` 是更稳的默认写法，但无论哪种都要保留 `app.Path` 断言。
- 需要类型库常量时，先 `gencache.EnsureModule('{2DF8D04C-5BFA-101B-BDE5-00AA0044DE52}', 0, 2, 8)`。

### 6.2 用实测代替估算
- 文本框真实高度/宽度：开 `AutoSize` 量一次再关（附录 5.3）。
- 自动排版规则（固废批量时总结）：文字超出页面底部 → 整页等比缩小；字小且页面空 → 逐步放大，碰到图片就停；流程图/公式/连线多的页 → 整体等比缩放，保持相对位置，不拆开重排；长标题自动缩小以放进标题框。
- 竖排成一列的窄标签（“捕收剂”）要加宽成横排；固定磅值行距改成倍数行距。

### 6.3 动画与切换
- 演讲类“全自动播放”：每页第一个效果 WithPrevious，其余 AfterPrevious。
- 含无限循环动画（`repeatCount="999000"`）的页：PowerPoint 导出视频会卡住，排练计时/自动换片会一直等。导出验证前先把次数改小；交付时提醒用户不要用自动换片。
- 平滑切换（Morph）+ 3D 旋转需要 PowerPoint 2019/365；WPS 基本显示不出来。
- 视频自动播放、跨页背景音乐（`numSld=999`）都要实际导出视频或放映验证。

### 6.4 字体与文件大小
- 比赛/他人电脑大概率没有特殊字体（思源黑体 Heavy、华文系列）：要么换成微软雅黑，要么嵌入字体。
- 嵌入字体会让文件变大很多（曾多出约 58MB）。我当时误判成“字体统一让文件变小”，后来更正。体积变化先查清原因再说。
- “仅嵌入演示文稿中使用的字符”可以减小体积，但在别的电脑上新加的字会换成其他字体。

### 6.5 其他
- Word 公式对象在批量处理中转成了静态图片，显示正常但不能编辑，要告诉用户。
- 删除跳转链接的规则（客户确认）：纯链接文字（如“工作原理视频”）连同括号整段删除；正文里带链接的词保留文字，只去掉链接。
- “3D 感”期望管理：矢量图加光影只能做到 2.5D。要真 3D（黏土、盲盒风）需要 AI 生图或 3D 软件，说清楚再做。
- pptx skill 自带的 `validate.py` 在本机跑不起来（schema 文件缺失，原稿也一样报错），多次如此。用“PowerPoint 能打开 + 逐页导出 + 结构自检”代替，并在交付说明里写明。

## 8. 协作与交付习惯

- **回复语言**：一律简体中文（用户收到英文后明确要求过两次）。
- **交付说明结构**：成品链接 → 改了什么（按客户条目逐条对应）→ 我额外加/改的 → 检查情况（验证了什么、没验证什么）→ 需要确认的点。
- **每轮保留旧版**，便于对比和回退。用户要求“恢复某页”时直接换回上一版。
- **额度不够时写交接**：已经两次（演讲稿、固废）写了给 Codex 的交接提示词。交接文档要写清：定稿文件、设计规范、构建命令、已知问题、验收标准。
- **临时文件夹会随会话删除**：项目在会话自带的临时文件夹里时，交接或长期保存前先移到固定位置（固废那单整合到了桌面 `固废课件_16x9美化版`）。
